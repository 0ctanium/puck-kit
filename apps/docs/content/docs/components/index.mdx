puck-kit ships **generic elements**, not pre-designed blocks. Each one maps to a real HTML element, has a
[style panel](/docs/styling/style-panel), and (for containers) a drop zone that *is* the element — so
`ul > li` and `grid > item` stay true in the output, with no wrapper divs.

## Structure

Layout primitives. Section, Container, the two Flex presets and Grid are **the same Box element** with
different default styles — everything remains editable.

## What every component has

<Accordions type="multiple">
<Accordion title="A styles prop and the style panel" id="styles">

Every component has a `styles` prop edited in the **Style** tab: per-breakpoint, per-state CSS properties.
The element gets the class `pk-<id>` and its CSS is compiled at render time. See [How styles work](/docs/styling).

</Accordion>
<Accordion title="An Advanced section (id, classes, aria-label)" id="advanced">

The `advanced` prop (`{ htmlId?, className?, ariaLabel? }`) sets an HTML `id` (for anchors like `#pricing`),
extra classes (for your own CSS or scripts) and an `aria-label`.

</Accordion>
<Accordion title="Inline mode: no wrapper divs" id="inline">

All components use Puck’s `inline: true`: the element itself receives Puck’s drag handle, so the editor
doesn’t add wrapper elements and layouts behave exactly like on the public page.

</Accordion>
<Accordion title="A tag select, when more than one tag makes sense" id="tag">

Components with several possible tags show a **Tag** select at the top of the Style tab (e.g. Box: `div`,
`section`, `article`, `aside`, `header`, `footer`, `nav`, `main`).

</Accordion>
</Accordions>
