## `usePuckKit` (recommended)

```tsx
'use client';
import { Puck } from '@puckeditor/core';
import { usePuckKit } from 'puck-kit/editor';

export function Editor({ data }) {
  const kit = usePuckKit(config, { fonts, onAddFonts }); // [!code highlight]
  return <Puck config={config} data={data} {...kit} />;
}
```

It returns the plugin plus the two `<Puck>` props a plugin can’t set:

<TypeTable
  type={{
    plugins: { type: 'Plugin[]', description: '`[puckKit plugin]` — stable across renders.' },
    viewports: { type: 'Viewport[]', description: 'Puck viewports matching your breakpoints (`toViewports(breakpoints)`), widest first.' },
    ui: { type: 'Partial<UiState>', description: 'Opens the editor on the **base** breakpoint (Puck would otherwise pick the viewport closest to the window width).' },
  }}
/>

Options can change over time (e.g. the font library after the user adds a font): the plugin reads them from a
small store, so its overrides never change identity and Puck doesn’t remount.

## Composing with your own props

Your own props compose as usual:

```tsx
<Puck
  config={config}
  data={data}
  {...kit}
  plugins={[...kit.plugins, myPlugin]} // keep the kit's plugin
  overrides={{
    headerActions: ({ children }) => <>{children}<SaveStatus /></>, // renders after the switcher
    fieldTypes: { image: MediaPicker, url: PagePicker }, // replace the kit's inputs
  }}
/>
```

<Callout type="warn" title="What the plugin owns">
  The plugin overrides `fields`, `drawer` and `drawerItem`. A `drawerItem` override of yours is replaced by the
  compact item. Your `headerActions` render after the breakpoint switcher, and your `fieldTypes.url` /
  `fieldTypes.image` replace the kit’s default inputs.
</Callout>

## The plugin alone

Prefer to manage viewports yourself? Create the plugin once — at module level or in `useMemo`:

```tsx
import { puckKit } from 'puck-kit/editor';

const plugin = puckKit({ fonts });

<Puck config={config} data={data} plugins={[plugin]} />;
```

Puck then uses its default viewports. You can pass `viewports={toViewports(getBreakpoints(config))}` yourself.
